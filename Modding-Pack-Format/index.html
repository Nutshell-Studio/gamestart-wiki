    Modding: the content pack format

    This page is for people making content packs (.gspack files). For installing packs and mods, start at Modding.

    Pre-release note: the format is version 3 and frozen for launch. Later game updates only add to it. A pack built for a newer game than the one you run is refused with a message that names both versions.

    What a content pack is

    A content pack is one file, <name>.gspack. Inside it is a small archive:

    • pack.json — the header: who made the pack, what it contains, and two identity hashes.
    • one folder per content kind — plain files, each declared in the header.

    Everything in a pack is data. No code runs from a pack, ever. The game checks every file against the header on every launch; a pack whose bytes do not match its header is refused, never partly loaded.

    The header (pack.json)

    Field Meaning
    packSchemaVersion 3
    effectVocabularyVersion 1
    packId Your pack's permanent id, reverse-DNS style: com.yourname.mypack. Never change it after you publish; players' saves remember it.
    packVersion Strict semantic version, e.g. 1.0.0. Bump it on every release.
    minGameVersion The oldest GameStart version this pack works with, e.g. 0.5.0.
    authorId Your name or handle. Shown on the MODS panel.
    priority Tie-break for load order between packs, -1000 to 1000. 0 is fine.
    dependencies Other packs this one needs (packId + minPackVersion).
    contents Every piece of content in the pack: { "contentId": "...", "kind": "..." }.
    replaces Which first-party or other-pack content this pack takes over: { "targetPackId": "com.gs.skills", "targetContentId": "..." }.
    <kind>Files One list per kind naming the files in the archive (gearFiles, talentFiles, skillLayoutFiles, localizationFiles, titleBankFiles, audioFiles, terminalGameFiles, …).
    fileHashes SHA-256 of every file's bytes. The creator tool fills this in.
    gameplayFileHashes A second hash for gameplay kinds, taken over the meaning of the file rather than its bytes. Also filled in by the tool.
    contentHash, gameplayHash The pack's two identities (see below). Filled in by the tool.

    You never write the hashes by hand. Build with the creator tool and it writes them; the game recomputes and checks them.

    Content kinds

    Kind (contents[].kind) What it changes Identity
    gear A skill definition: its tiers, costs and effect, built from the fixed effect vocabulary. New ids extend the first-party set; an existing id needs a replaces entry. gameplay
    talent_tree The talent tree behind the skills. Exactly one tree is in effect; a pack changes it by replacing the first-party tree id. gameplay
    skill_layout Which skills are purchasable and which tool slot each active skill sits in. Exactly one layout is in effect; declare it under the first-party layout id and replace it. gameplay, except the enabled flag, which is cosmetic
    localization A text table (gs-strings/1): any line of the game's text, for any language. Untranslated lines keep their English. cosmetic
    title_bank Word banks for the fictional titles on the boxes (sp3aNames, adjectives, nouns). Real trademarks are refused. cosmetic
    audio Replacement sounds for the nine fixed slots: pick, place, refuse, complete, chime, footstep_a, footstep_b, ambient_loop, kiosk_loop. WAV, up to 2 MB per one-shot and 8 MB per loop. cosmetic
    terminal_game A web mini-game for the store kiosks: a folder with game.json and its page files. cosmetic
    title_policy Landing. Which titles fill the store: source, decade filter, NSFW filter, Steam cap. gameplay

    Kinds the game accepts in the header but does not use in a player build are listed on the MODS panel with a reason: quiz and library_scenario (retired features), rank_ladder (developer lane only), store_layout, scatter, sku_catalog, start_state (studio authoring only). A pack made only of those is refused as "kind not supported".

    The two identities

    • Gameplay identity covers everything that changes what the night simulates. It is written into a save's pack lock. A save made with a gameplay pack refuses to continue if that pack is removed or changed; restore the pack and it loads again. In co-op, every player must have the same gameplay packs.
    • Content identity covers every byte. Cosmetic kinds (translations, title banks, sounds, terminal games) only move this one, so installing them never affects a save or a co-op session.

    Load order and replacing

    Packs load in the order the MODS panel shows: higher priority first, then by packId. Two packs may not declare the same content id unless one of them says so with replaces; a silent "last one wins" does not exist. If the set of packs cannot be resolved, no mod content is applied and the MODS panel says why.

    Limits

    • JSON files: 1 MB each.
    • Audio: 2 MB per one-shot slot, 8 MB per loop slot.
    • No other size limit beyond what Steam Workshop allows.
    • File names inside a pack are plain relative paths; .. and absolute paths are refused.
    • Program and script files are refused whatever the kind: .exe .dll .cs .bat .cmd .ps1 .msi .jar .sh and the other operating-system executable types, plus the game engine's own scene, object and shader files. A terminal game's page files (.html .css .js .wasm, images, fonts, sounds) are fine; they only ever run inside the kiosk's sandboxed page.

    Refusal codes

    When a pack does not load, the MODS panel shows a code. The common ones:

    Code What to do
    PACK_HASH_MISMATCH The file was changed after it was built. Rebuild it, or re-download it.
    PACK_SCHEMA_UNSUPPORTED The pack is for a different format version. Rebuild it with the current tool.
    PACK_GAME_VERSION The pack needs a newer GameStart. Update the game, or ask the author for an older build.
    PACK_KIND_UNSUPPORTED Nothing in the pack is a kind this build uses.
    PACK_DUPLICATE_ID Two packs declare the same content without a replaces. Remove one, or ask the author to declare the replacement.
    PACK_DEPENDENCY_MISSING A pack this one needs is not installed or is too old.
    PACK_ID_INVALID An id or a version string is malformed.
    PACK_UNKNOWN_FIELD A file has a field the game does not know, or the archive holds a file the header does not declare.
    PACK_SIZE_LIMIT A JSON file is over 1 MB, or a sound is over its slot's limit.
    PACK_PATH_TRAVERSAL, PACK_ABSOLUTE_PATH, PACK_CODE_FORBIDDEN The archive contains a path or a file type that is never allowed.

    Building a pack

    Use the creator tool, gs-mod-cli: a small command-line program, downloaded as a zip from the GameStart releases page on GitHub (needs the .NET 8 runtime; unzip and run from a terminal):

    gs-mod-cli init my-pack --kind skills --pack-id com.yourname.mypack --author yourname
gs-mod-cli validate my-pack
gs-mod-cli build my-pack -o my-pack.gspack
gs-mod-cli inspect my-pack.gspack
gs-mod-cli identity my-pack.gspack

    init writes a starter folder with a worked example for the kind (skills or translation today; the other kinds follow), validate reports every problem the game would report, build writes the hashes and the archive and refuses to write a pack the game would not load, inspect shows what a finished pack contains, and identity prints just the two hashes. Then drop the .gspack into your Mods folder (the MODS panel's "Open mods folder" button) or publish it — see Publishing to Steam Workshop.
